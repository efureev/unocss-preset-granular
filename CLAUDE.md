# unocss-preset-granular

Yarn 1 workspaces-монорепо вокруг `@feugene/unocss-preset-granular` — UnoCSS-пресета,
который собирает CSS, темы и `safelist` из пакетов-провайдеров по контракту
`GranularProvider`. Состав: пресет (`packages/unocss-preset-granular`), три
провайдера (`packages/{simple,extra-simple,heavy}-package`), пакет доп-правил
(`packages/unocss-mini-extra-rules`), шесть демо-приложений (`apps/app-1..6`),
которые работают как интеграционные тесты контракта, и три стенда замера веса
(`apps/bench-{zero,one,pruned}`).

## Жёсткие правила

**Пакетный менеджер — Yarn 1** (`packageManager: yarn@1.22.22`, `yarn.lock`).
`npm install`/`pnpm` перепишут дерево и сломают workspace-симлинки, через которые
приложения видят пакеты.

**Приложения и провайдеры потребляют `dist/`, а не исходники.** Проверено:
`@feugene/unocss-preset-granular/node` из `apps/app-1` резолвится в
`packages/unocss-preset-granular/dist/node.js`. При этом `paths` в
`apps/*/tsconfig.json` указывают на `src/` — типы обновляются мгновенно, поведение
нет. Правка в `src/` пресета без пересборки не влияет ни на что, кроме типов, и
ошибки при этом не возникает.

**Порядок сборки — часть контракта, а не удобство.** Провайдеры на своей сборке
импортируют `@feugene/unocss-preset-granular/vite` и `/contract` из `dist`.
Единственный безопасный путь — `yarn build:all` (пресет → доп-правила → провайдеры →
приложения). Сборка приложения поверх устаревшего `dist` пресета проходит успешно и
даёт неверный CSS.

**Граница browser/node в пресете реальная и её легко пробить.** Экспорт `.`
не должен получать `node:`-импорты; разрешены они только `./node` и `./vite`
(build-слой: `granularCssAssetsPlugin` ходит в FS). Импорт из `/node` или
`/vite` в код, попадающий в браузерный бандл (включая `config.ts` компонентов
провайдера), тянет `node:fs` в клиент — сборка при этом не падает.

**Токены тем пишутся БЕЗ префикса `--`.** Генератор дописывает его сам
(`preset.node.ts`). `tokens: { '--x': ... }` даёт в CSS `----x` и молча ломает тему.

**`docs/en` и `docs/ru` — зеркала.** Правка в одном без парной правки в другом
разъезжает документацию; сейчас файлы синхронны построчно.
