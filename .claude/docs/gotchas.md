# Грабли

> **Применяется когда:** перед сборкой или проверкой итогового CSS; когда поведение
> необъяснимо, а ошибок нет.
> **Не нужно:** когда нужна просто команда — это `workspace.md`.
> **Смежное:** `.claude/docs/workspace.md`, `docs/ru/troubleshooting.md`.

Пункты записаны от симптома. Общая черта почти всех: **ошибки не возникает**,
сборка зелёная, ломается только результат.

## «Правлю пресет, но ничего не меняется»

Приложения и провайдеры резолвят пресет в `dist/`, а не в `src/`. Проверено:

```
@feugene/unocss-preset-granular/node  →  packages/unocss-preset-granular/dist/node.js
```

При этом `paths` в `apps/*/tsconfig.json` указывают на `src/` — редактор и `tsc`
показывают свежие типы, рантайм работает со старым бандлом. Лечится пересборкой в
правильном порядке: `yarn build:all` (или `yarn build:granular && yarn build:packages`,
если приложения не нужны).

Тот же механизм наоборот: провайдеры импортируют `/vite` и `/contract` из `dist`
пресета **на своей сборке**. Пересобрать провайдер поверх устаревшего пресета —
получить провайдер, собранный по старому контракту, без единого предупреждения.

## «Класс `p-5` из компонента провайдера не попал в CSS»

По убыванию вероятности:

1. В `uno.config.ts` приложения нет `content: granularContent(granularOptions)`.
   `@unocss/vite` игнорирует `content`, возвращённый пресетом.
2. Провайдер собран без `granularChunkFileNames()` — SFC-чанки лежат в плоском
   `dist/chunks/`, который не сканируется.
3. Компонент не выбран в `components` и не достижим через `dependencies`.
4. `packageBaseUrl` провайдера собран как литеральный `new URL('..', import.meta.url)` —
   бандлер подменил его на `data:`-URL, скан-директории схлопнулись.
5. Класс динамический (`` :class="`p-${n}`" ``) — статический extractor его не видит.

Диагностика: `DEBUG=granular:scan yarn build:apps` покажет, какие директории реально
попали в скан, а `npx granular doctor` — нарушения layout-контракта.

## «Тема применилась, но переменные выглядят как `----brand`»

Ключи в `tokens` пишутся без `--`; префикс дописывает генератор. Ловушка живучая:
примеры в `docs/*/themes-and-tokens.md` и `component-authoring.md` долго были
написаны неверно (сейчас исправлены).

## «`tokenDefinitionsFromCss` бросает ошибку про flat top-level blocks»

Парсер понимает только плоские блоки верхнего уровня: `@media (…) { :root { … } }`
и вложенные `.dark { :root { … } }` он выразить в паре `{ selector, tokens }` не
может и потому пропускает — при `strict: true` (дефолт) с ошибкой, иначе с
`console.warn`. Раньше он молча отдавал внутренний селектор как безусловный.
Лечится расплющиванием CSS-файла темы; `:root`, вложенный в `.dark`, в браузере
всё равно не матчится. Точка с запятой у последнего объявления в блоке
необязательна.

## «Токен разрешается в пустоту, а сборка зелёная»

Включена обрезка (`pruneTokens.mode: 'on'`), и объявление токена удалено как
неиспользуемое. Три источника, в порядке частоты:

1. **Разметка приложения.** Пресет видит компоненты провайдера и НЕ видит ваш
   `App.vue`. Написанный там `bg-[var(--brand)]` для него не существует.
   Лечится `pruneTokens.appSources: { dirs: ['./src'] }`.
2. **Имя собирается в рантайме** (`` `var(${nameFromProp})` ``). Особенно
   коварно, когда имя лежит в ОБЩЕМ модуле: бандлер выносит его в чанк вне
   `components/<Name>/`, и канал строковых литералов туда не заглядывает.
   Лечится `dynamicTokens` у компонента, который токен читает.
3. **Опечатка в `keep`.** Строка есть, а токена с таким именем нет.

Всё три показывает `granular prune` — он же печатает, читались ли вообще
исходники приложения:

```bash
node packages/unocss-preset-granular/dist/bin.js prune ./granular.options.mjs
```

На время разбирательства верните `mode: 'report'`: план считается, CSS
эмитится прежним.

Отдельно: при `mode: 'off'` (по умолчанию) обрезка не читает ни одного лишнего
файла и не меняет эмиссию ни на байт — если CSS поехал при выключенной
обрезке, причина не здесь.

## «Как проверить приложение»

`yarn workspace @feugene/granular-app-1 build && … verify` — второй шаг сверяет
собранный CSS с `apps/app-1/expected-css.mjs`. Всё разом:
`yarn build:all && yarn verify:apps`.

Скриптов `test`/`test:run` у приложений больше нет (они ссылались на
несуществующий `vitest.config.ts` и просто падали).

## Как убедиться, что цепочка действительно работает

Сквозная проверка: собрать всё и посмотреть в итоговый CSS приложения.

```bash
yarn build:all
cat apps/app-3/dist/assets/spkg-*.css
```

Ожидаемо там `.x-sp-test` с раскрытыми утилитами (`display:flex`, `gap`, размер
шрифта) — это значит, что extractor дошёл до скомпилированного SFC провайдера, то
есть контракт сканирования исполнен. Пустой или отсутствующий файл — сигнал, что
цепочка порвана; ошибок при этом не будет.

## Что не является поломкой

- `npx tsc -p tsconfig.json --noEmit` и `yarn lint` должны быть ЗЕЛЁНЫМИ.
  Падение lint с `TypeError: Cannot read properties of undefined (reading 'Cjs')`
  означает, что в дерево вернулся TypeScript 7 — проверь `resolutions` в
  корневом `package.json`.
- В `apps/app-3/dist/assets/` есть пустой `granularity-*.css` — так собирается
  сейчас, отдельно не расследовалось.
