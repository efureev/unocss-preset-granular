# Git, версии и релиз

> **Применяется когда:** коммит, ветка, PR, версия, changelog, тег, публикация,
> вопросы про CI.
> **Не нужно:** при обычной разработке без выпуска.
> **Смежное:** `.github/workflows/ci.yml`, `.claude/docs/workspace.md`.

## Коммиты

История ведётся в стиле Conventional Commits: `feat:`, `fix:`, `chore:`, `docs:`,
`test:`, `deps:`. Часть старых коммитов — односложные (`fix`, `docs`); ориентируйся
на развёрнутые, они новее.

Основная ветка — `main`. Коммить и пушить только по явной просьбе.

**Авторство — только пользователя.** Ни `Co-Authored-By: Claude`, ни строки
«Generated with Claude Code», ни любой другой подписи ассистента — ни в коммите,
ни в аннотации тега, ни в описании PR. Правило постоянное; шаблон инструмента,
предлагающий такой трейлер по умолчанию, здесь не применяется.

## Два независимых релизных трека

В репозитории публикуются два пакета, у каждого свой префикс тега:

| Пакет | Тег | Что триггерит |
|---|---|---|
| `@feugene/unocss-preset-granular` | `v<semver>` | тесты → сборка → publint → npm → GitHub Packages |
| `@feugene/unocss-mini-extra-rules` | `unocss-mini-extra-rules-v<semver>` | typecheck → сборка → publint → npm → GitHub Packages |

Провайдеры (`simple-package`, `extra-simple-package`) и приложения не публикуются.

CI сверяет тег с `version` в `package.json` и падает при расхождении — то есть
порядок такой: сначала поднять версию в `package.json` и закоммитить, потом ставить
тег. Публикация идёт из артефакта сборки, а не из свежего билда на раннере.

В списке тегов есть исторический `unocss-preset-granular-v0.2.2`, который под маску
`v*` не подпадает и ничего не запускал. Актуальный формат для пресета — `v0.4.0`.

## Сквозная проверка контракта в CI

Job `verify-contract` гоняет `yarn build:all` (пресет → доп-правила →
провайдеры → приложения) и следом `yarn verify:apps` — сверку собранного CSS
каждого приложения с его `expected-css.mjs`. От него зависят **обе** публикации:
пресет, ломающий провайдеров или приложения, до npm не доедет.

Зачем отдельно от юнит-тестов: успешная сборка ничего не доказывает — она
остаётся зелёной и тогда, когда классы компонента молча пропали из CSS. Такое
даёт не та scan-директория, не доехавший в `dist` CSS темы, разъехавшийся
`packageBaseUrl`. Ловит это только сверка с ожиданиями.

Артефакт сборки пресета здесь намеренно НЕ переиспользуется: порядок сборки —
часть контракта, провайдеры импортируют `/vite` и `/contract` из `dist`, и
сборка поверх устаревшего `dist` проходит успешно, давая неверный CSS.

## Линт и typecheck пресета

Живут в job `test-unocss-preset-granular`, шагами перед тестами. Матрица там
node 22/24, но оба шага помечены `if: matrix.node == 24` — от версии Node они
не зависят, гонять их дважды незачем.

Скриптов у пакета два, и путать их нельзя:

| Скрипт | Где |
|---|---|
| `lint` (`eslint --fix src`) | локально |
| `lint:check` (`eslint src`) | CI — `--fix` молча починил бы нарушение и вернул ноль |

`typecheck` — это `tsc --noEmit -p tsconfig.json`, то есть ШИРЕ, чем `tsc` внутри
`build`: тот идёт по `tsconfig.build.json`, где тесты исключены. Разница не
теоретическая — первый же прогон поймал ошибку типов в тесте.

## Что CI НЕ проверяет

- юнит-тестов у провайдеров нет — они проверяются только через `verify:apps`.

## Версия пресета и workspace-симлинки

Бамп `version` у пресета обязан сопровождаться бампом диапазона
`@feugene/unocss-preset-granular` во ВСЕХ потребителях внутри репозитория
(`packages/{simple,extra-simple}-package`, `apps/app-1..6`) — и в примере
`package.json` в `docs/{en,ru}/authoring-providers.md`.

Иначе диапазон перестаёт покрывать локальную версию, yarn считает workspace-пакет
неподходящим и тихо ставит ОПУБЛИКОВАННУЮ версию из npm во вложенные
`node_modules`. Симлинк исчезает, репозиторий начинает собираться против чужого
кода, а новый API «не существует». Симптом — `SyntaxError: The requested module
… does not provide an export named …` при загрузке `vite.config.ts` провайдера.

Проверка после бампа: `ls -la node_modules/@feugene/unocss-preset-granular`
должен быть симлинком, а `packages/*/node_modules/@feugene` — отсутствовать.

## Публикация

Публикуется содержимое `dist` (`files: ["dist"]`) из корня каталога пакета, с
provenance. Зеркало в GitHub Packages идёт под scope `@efureev` и помечено
`continue-on-error` — его падение релиз не блокирует.

Лицензия — MIT: `LICENSE` лежит в корне репозитория и продублирован в
`packages/unocss-preset-granular/` и `packages/unocss-mini-extra-rules/`, чтобы
попадать в npm-тарболл (`files: ["dist"]` его не исключает — npm кладёт LICENSE
всегда). Копии должны совпадать с корневой.
