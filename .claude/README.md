# Устройство `.claude/` в этом репозитории

Этот файл движок Claude Code **не читает никогда** — каталог `.claude/` не
сканируется на память, автозагружается только `rules/`. Поэтому справка лежит
здесь: она ничего не стоит в контексте.

## Схема

```
CLAUDE.md                 ядро, грузится всегда
.claude/
  rules/*.md              грузятся ЛЕНИВО, по маске paths:
  docs/*.md               не грузятся никогда, читаются явным Read
  settings.json           allow-list команд, читает харнесс (не в контексте)
  settings.local.json     личное, игнорируется репозиторием
  README.md               этот файл
```

## Два механизма загрузки

**Всегда:** `CLAUDE.md` (корневой, пользовательский `~/.claude/`, и вверх по дереву),
плюс любой файл в `.claude/rules/` **без** ключа `paths:`.

**Лениво:** файл в `.claude/rules/` с ключом `paths:` подтягивается в момент, когда
файл под маской попал в работу. Триггер — **чтение**, а не правка: правило приезжает
уже на `Read`, ждать `Edit` не нужно.

Обе ветки проверены канарейкой на Claude Code 2.1.212 в этом репозитории:
правило с `paths: ["packages/unocss-preset-granular/src/**"]` отсутствовало в чистой
сессии и появлялось после чтения `src/core/dedupe.ts`; правило без `paths:` было в
контексте чистой сессии сразу.

Проверять так (обязательно оба прогона — один не отличает «грузится всегда» от
«загрузилось по триггеру»):

```bash
printf -- '---\npaths:\n  - "packages/unocss-preset-granular/src/**"\n---\n\n# K\n\nКодовое слово: ZORBLAX-7741\n' \
  > .claude/rules/_canary.md

claude -p 'Не используй инструменты. Есть ли в контексте ZORBLAX-7741? Только ДА или НЕТ.' \
  --model haiku --disallowedTools "Read,Grep,Glob,Bash,Task"

claude -p 'Прочитай packages/unocss-preset-granular/src/core/dedupe.ts. Затем перечисли файлы правил, появившиеся в контексте, и напиши ZORBLAX-7741, если видишь его.' \
  --model haiku

rm .claude/rules/_canary.md
```

Формулировку второго вопроса не упрощай до «есть ли в контексте X»: haiku
интерпретирует это как «есть ли X в прочитанном файле» и отвечает НЕТ при
работающем механизме. Ложноотрицательный ответ здесь уже случался дважды —
проси явно «посмотри в СВОЙ контекст (system-reminder), а не в файл».

## При совпадении нескольких масок грузится только одно правило

Проверено канарейкой на 2.1.212. Два правила с масками
`packages/unocss-preset-granular/**` и `**/README.md`, оба матчат
`packages/unocss-preset-granular/README.md`. В контекст приезжает **только одно** —
то, у которого маска `**/README.md`. Победитель не меняется при перестановке
содержимого между файлами, то есть выбор идёт по паттерну, а не по имени файла или
порядку чтения каталога.

Что именно считается «более специфичным» — не выяснено (две точки данных мало);
достоверно только то, что **пересечение масок молча подавляет одно из правил**.
Практический вывод: не рассчитывай, что на файл приедут оба правила, и после любой
правки масок перепроверяй канарейкой, какое из них выигрывает.

Известное пересечение в текущей конфигурации: `docs.md` (`**/README.md`) перекрывает
`preset-core.md`, `provider-packages.md` и `apps.md` на файлах `README.md` внутри
`packages/*` и `apps/*`. Выигрывает `docs.md` — для правки README это верное
правило, поэтому пересечение оставлено намеренно.

## Правила поддержки

- **`paths:` обязателен у каждого файла в `rules/`.** Без него правило висит в
  каждой сессии — ровно та трата, ради снятия которой всё и сделано.
- **Маски матчатся от корня репозитория, `**` обязателен для вложенности.**
  `docs/**` поймает `docs/ru/architecture.md`; `*.test.ts` не поймает ничего —
  нужен ведущий `**/`. Ошибка ничем себя не обнаруживает: правило просто не придёт.
- **Не подключай правила через `@`-импорт из `CLAUDE.md`.** Импорт отменяет ленивую
  загрузку, и файл окажется в контексте дважды.
- **Каждый файл `docs/*` должен быть строкой в таблице «Читать когда» в `CLAUDE.md`.**
  Док без ссылки из ядра невидим.
- **Не дублируй в `CLAUDE.md` списки скиллов и агентов** — харнесс инжектит их сам.
- Правишь маску — перепроверь канарейкой. Иначе изменение области действия правила
  нельзя отличить от его отключения.

## Текущие правила и их маски

| Файл | Маска | Область |
|---|---|---|
| `rules/preset-core.md` | `packages/unocss-preset-granular/**` | ядро пресета, контракт, node-слой, тесты |
| `rules/provider-packages.md` | `packages/{simple,extra-simple}-package/**`, `packages/unocss-mini-extra-rules/**` | пакеты-провайдеры |
| `rules/apps.md` | `apps/**` | демо-приложения |
| `rules/docs.md` | `docs/**`, `**/README.md`, `**/README.ru.md` | документация |

Проверено по одному прогону на каждое правило: чтение `src/core/dedupe.ts`,
`packages/simple-package/src/components/XTest1/config.ts`, `apps/app-3/uno.config.ts`
и `docs/ru/architecture.md` подтягивает ровно одно ожидаемое правило.
О пересечении на `README.md` — см. раздел выше.

## Скиллы и агенты: почему их нет

Каталоги `skills/` и `agents/` намеренно не заведены. Скилл оправдан под процедуру,
которая в репозитории уже повторялась и шаги которой подтверждаются кодом или
историей; выдуманная процедура с видом инструкции опаснее её отсутствия — ей будут
следовать.

Кандидаты, если практика закрепится:

- **`granular-verify`** — сквозная проверка контракта: `yarn build:all` + чтение
  итогового CSS приложения. Сейчас это две команды из `docs/gotchas.md`; оформлять
  в скилл стоит, если появится больше шагов или разбор вывода.

Ловушка на будущее: харнесс разбирает как определения агентов **все** `.md` в
`.claude/agents/`. На 2.1.212 файл без frontmatter игнорируется, но перед тем как
класть туда `README.md`, это надо перепроверить:
`claude -p 'Перечисли имена доступных subagent_type через запятую.' --model haiku`.
