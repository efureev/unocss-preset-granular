> **Применяется когда:** правишь `uno.config.ts`, `vite.config.ts` или исходники
> демо-приложений `app-1..6` и стендов замера `bench-*`.
> **Не нужно:** при работе с пресетом и провайдерами — там свои правила.
> **Смежное:** `docs/ru/usage-in-apps.md`, `.claude/docs/gotchas.md`.

Приложения — интеграционные тесты контракта. `app-1` — минимальный кейс,
`app-3` — кросс-провайдерные зависимости (тянет `simple-package` транзитивно через
`extra-simple-package`), `app-4` — связка с `@feugene/unocss-mini-extra-rules`,
`app-5` — рантайм-переключение тем, `app-6` — `themes.define`: собственные темы
приложения вместо провайдерских `light`/`dark`.

## `bench-*` — не тесты контракта, а измерительные стенды

`apps/bench-zero`, `apps/bench-one` и `apps/bench-pruned` меряют вес и живут по
своим правилам. Три отличия от `app-1..6`, каждое обязательное:

1. **Обвязка сборки у трёх стендов совпадает.** Отличаться им дозволено ровно
   одним шагом: `bench-one` = `bench-zero` + пресет и компонент,
   `bench-pruned` = `bench-one` + `pruneTokens.mode: 'on'`. Любая другая
   разница делает дельту не дельтой библиотеки.
2. **Трансформеры запрещены.** `transformerCompileClass` схлопывает классы в
   `.uno-<hash>`, после чего метрика классов меряет количество хэшей.
3. **В `App.vue` нет ни одного собственного класса** — иначе `app-*.css`
   перестаёт быть атрибутируемым. И помни: UnoCSS сканирует ТЕКСТ файла, так
   что имя утилиты нельзя писать даже в комментарии (проверено — генерируется).

У стендов, кроме `expected-css.mjs`, есть `expected-budget.mjs`; его сверяет
`node scripts/report-css-budget.mjs --strict`.

## Обязательная форма `uno.config.ts`

```ts
const granularOptions: PresetGranularNodeOptions = { providers: [...], components: [...], layer: 'granular' }

export default defineConfig({
  presets: [presetMini(), presetGranularNode(granularOptions)],
  content: granularContent(granularOptions),   // ← без этого классы не доедут
})
```

`@unocss/vite` читает `content.filesystem` и `content.pipeline.include` только из
верхнего уровня user-конфига — `content`, возвращённый пресетом, он игнорирует.
Забыть `granularContent` — самая частая поломка, и она не даёт ни ошибки, ни
предупреждения: просто исчезают утилитарные классы компонентов.

**Один и тот же объект опций** должен уходить и в `presetGranularNode`, и в
`granularContent` — на идентичности объекта держится мемоизация резолва.
Альтернатива — `defineGranular(options)` с его `preset()`/`content()`.

## Селекторы компонентов

Только квалифицированная форма `'providerId:Name'` или объектная
`{ provider, names: [...] }`. Короткое `'Name'` бросает исключение — оно допустимо
исключительно внутри `dependencies` компонента.

`components: 'all'` осмысленно только для демо: оно отключает granular-отбор,
ради которого пресет и существует.

## Проверка приложения — не сборка, а `verify`

У каждого приложения есть `expected-css.mjs`: список того, что обязано (и что НЕ
должно) оказаться в собранном CSS, с пояснением на каждую строку. Прогон:

```bash
yarn build:all && yarn verify:apps          # всё
yarn workspace @feugene/granular-app-3 verify   # одно (после его build)
```

Сборка зелёная и тогда, когда классы компонентов молча исчезли из CSS — именно
этот отказ пресет и должен предотвращать, поэтому «собралось» проверкой не
считается.

**Меняешь разметку `App.vue` или состав компонентов — правь `expected-css.mjs`.**
Ожидание должно опираться на маркер, которого нет в исходниках самого приложения
(например, `var(--brd)` встречается только в шаблоне компонента-донора). Иначе
проверка проходит и без `granularContent`, то есть не проверяет ничего.

## Известное расхождение

`apps/*/tsconfig.json` в `paths` мапят пресет на `src/`, тогда как рантайм резолвит
`dist/`. Типы и поведение расходятся; для `/vite` записи в `paths` вообще нет.
