# AUDIT — `@feugene/unocss-preset-granular`

Реестр дефектов и расхождений, подтверждённых воспроизведением. Аудит от 2026-08-08, пакет v0.7.1; дополнен
2026-08-22 по итогам разбора реального потребителя (`@feugene/granularity`, пресет 0.10.0/0.10.1) и 2026-08-28 —
по итогам работы над `granular tokens` и разбора фидбека того же потребителя (пресет 0.13.0 → 0.15.0).
Исправленные пункты из файла удаляются.

## Находки

Открытых находок нет — всё найденное исправлено (см. итог внизу). Находка от 2026-08-22
(`packageExports` вычищал соседние subpath'ы компонента) закрыта в 0.10.1: ключом компонента
считается ровно `<keyPrefix><Name>`, вложенные ключи и паттерны генератор не трогает.

Три находки от 2026-08-28 закрыты в том же изменении, которым добавлена команда `granular tokens`. Все три —
один и тот же дефект в трёх местах: **на вопрос «какое значение у токена» в пакете было три независимых ответа**,
и два из них расходились с эмитируемым CSS.

1. `ExplainReport.tokens[].effective` считался по `themes.tokenRegistry`, куда четвёртый слой
   (`themes.tokenOverrides`) не входит — он применяется только на эмиссии, в `generateThemeBlocks`. На любом
   приложении, перебивающем токен компонента (например `apps/app-2`), `explain` печатал ДО-override значение и
   `overridden: false` — ровно там, где токен как раз перебит.
2. `getGranularThemeManifest(…, { includeTokens: true })` — тот же источник, тот же дефект. Тяжелее первого: он
   нарушал записанный инвариант «манифест строится из ТОЙ ЖЕ резолюции, что и CSS». Селекторы совпадали,
   значения — нет, а именно к значениям обращается приложение, рисующее превью палитры.
3. `computeTokenConflicts` не учитывал `strictTokens`, тогда как генератор CSS отбрасывает override токена,
   не объявленного ни одним пакетным слоем. `doctor` мог назвать финальным значение, которого в CSS нет.
   Наблюдаемость была низкой ровно из-за фильтра `sources.length > 1`: отброшенный токен обычно даёт цепочку
   длины 1 и отсеивался. Конструкция достижима — два override'а на один ключ (плоская и вложенная формы,
   целящиеся в один селектор).

Лечение общее: раскладка слоёв вынесена в `core/tokenLayers.ts` (`collectTokenLayers`), из неё сериализуется CSS
и из неё же читают `doctor`, `explain`, `granular tokens` и манифест тем. Проверка того, что поведение CSS не
поехало, — `verify-apps` на всех шести приложениях плюс `preset.node.overrides.test.ts` (19 тестов), который при
рефакторинге не правился ни разу.

## Неконсистентности (код ↔ доки ↔ правила)

Расхождений не осталось. `docs/en ↔ docs/ru` — синхронны (`yarn check:docs`: 13 пар, зелёно).
README-пример компилируем против текущего API.

## Оптимизации

1. `PresetGranularResolution` мог бы нести `registry`. С 2026-08-28 цена выросла: `buildRegistry(resolution.providers)`
   строят заново уже три потребителя — `computeUndeclaredDependencies` (`doctor.ts`), `granularExplain` и
   `granularTokens`.
2. Остальная кэш-архитектура подтверждена и образцова: мемоизация по идентичности работает, LRU-кэш CSS с
   mtime-инвалидацией, разбор общих чанков один раз на инспекцию. Кэшей теперь шесть — добавился индекс
   потребления токенов (`fs/tokenUsage.ts`), построенный по тому же контракту (`WeakMap` по идентичности `options`).
3. `granular tokens` и `doctor` в одном процессе делят и этот индекс, и LRU чтения CSS, поэтому обход `dist`
   у второй команды почти бесплатен. Отдельного замера нет — стоит сделать, если `doctor` попадёт в watch-режим.

## Куда расти

1. Watch/HMR для авторов провайдеров — главный DX-капкан репозитория (правка `src/` без пересборки молча ничего не
   меняет).
2. Расширение `doctor` до полного «контрактного линтера»: существование задекларированных `cssFiles`, бинарно-безопасная
   проверка browser/node границы провайдера, метрика over-include safelist. Первый шаг сделан 2026-08-28 —
   `token-undefined` (потребляемый токен, которого не задаёт ни один слой); остальные три пункта открыты.
3. Политика версии контракта к 1.0: как будет выглядеть миграция на версию 2 (поддержка N−1, парные релизы, коды ошибок
   для смешанных графов).
4. Тип-тесты публичного API (`expect-type`/`tsd`) как замок на exports map и «открытые union» отчётов.
5. Бенчмарк резолюции в CI: цифры «1 мс vs 30 мс» из правил — превратить в регрессионный тест.
6. Структурные токены тем в браузерном пресете (`tokenDefinitions` — чистые данные без FS): либо эмитить их
   inline-preflight'ом, либо явно задокументировать в SPEC, что темы — прерогатива node-слоя. С 2026-08-28
   первый вариант стал дешевле: `collectTokenLayers` лежит в `core/` и от FS не зависит — браузерному пресету
   не хватает только сериализатора.

Прогоны после исправлений (2026-08-09): `yarn test:granular` — 345/345; coverage выше порогов; `tsc --noEmit`,
`yarn lint`, `yarn check:docs`, `yarn verify:apps` — зелёные; `npm pack` чистый; publint чистый; кириллицы в строковых
литералах `src` не осталось.

Прогоны после изменения 2026-08-28: `yarn test:granular` — 429/429 (30 файлов); coverage 94.9 / 87.5 / 97.7 при
порогах 90 / 85 / 90; `tsc --noEmit`, `yarn lint`, `yarn check:docs` (13 пар), `yarn build:all` — зелёные;
`verify-apps` — 6/6 приложений, 54 проверки, то есть эмитируемый CSS не изменился ни на байт при переписанном
генераторе блоков токенов; publint чистый; `grep 'node:' dist/index.js` пуст — граница browser/node цела.

Исправлено в 0.15.0 (заведено потребителем `@feugene/granularity`, 78 компонентов, против 0.14.1; обе его
находки воспроизведены минимальным стендом на data-URL): раскладка инлайнимых base/tokens/тем вынесена в
`resolveInlinedCssSources` и стала общей для эмиссии и отчётов. Закрыло три расхождения разом.

1. `token-undefined` был слеп к вытеснению через `themes.tokensFile`. Эмиссия ЗАМЕНЯЕТ провайдерский файл при
   app-override, а диагностика складывала оба в одно множество «заданного»: токен, снесённый подменой,
   оставался для неё заданным — и она молчала ровно в том случае, ради которого заведена. На реальном
   приложении подмена `tokens.css` роняла theme-CSS с 22 504 до 15 703 байт, одиннадцать переменных
   разрешались в пустоту при зелёной сборке. Правка 0.14.1 добавила `themeFiles` в тот же цикл сложения и
   потому дыру не закрыла.
2. `granular tokens` про инлайнимый CSS не знал вовсе: провайдер, отдающий палитру обычным `tokens.css`,
   получал отчёт, где ВЕСЬ его набор лежит в группе «ничьих».
3. Найдено при разборе, в исходном отчёте не было: доктор читал `provider.theme.themes[name]`, не глядя на
   `tokenDefinitions`, тогда как `resolveThemes` разводит их через `else if` — структурная тема вытесняет
   файловую, и файл в CSS не уезжает. Доктор разбирал файл-призрак.

Обход идёт по `resolution.themes.items`, что закрывает третью находку по построению. Заодно `pickThemeUrl`
перестал подписывать app-override как `provider '<id>'`: метка стала происхождением токена в отчёте.

Урок тот же, что и в 0.14.0, и он теперь записан инвариантом: множество «заданного» нельзя считать вторым
проходом по своим правилам — только брать из раскладки эмиссии.

Исправлено 2026-08-28 (см. «Находки»): единый источник значений токенов `collectTokenLayers` вместо трёх
расходившихся; `explain` и манифест тем научились видеть `themes.tokenOverrides`; `computeTokenConflicts` —
`strictTokens`. Добавлено там же: команда `granular tokens` (токены компонента по происхождению — свои, общие,
ничьи — с цепочкой слоёв за каждым значением и режимом `--deep` для под-компонентов), диагностика
`token-undefined` и поле `DoctorReport.undefinedTokens`. Отброшенный `strictTokens` слой перестал быть невидимым:
он остаётся в цепочке с пометкой `skipped`, потому что «override написан и отброшен» и «override не писали» —
разные факты, а сообщал о первом только `console.warn`, тонущий в CI.

Исправлено и удалено из реестра (M1–M4, m5–m10, n11–n12): NUL-байт в `cssAssets.ts`; граница `/vite` согласована с
SPEC §9 / `preset-core.md` / CLAUDE.md / `cli.md`; `tokenDefinitionsRef` материализуются только для тем, которые могут
стать активными; `doctor` получил диагностику `token-prefix`; все bare `Error` заменены типизированными классами
(`InvalidComponentKeyError`, `GranularCssSourceError`, `GranularTokenParseError`, `GranularOptionsLoadError`),
а `InvalidProviderError` наконец экспортирован из `.`; `getGranularComponentCss` оборачивает чтение в
`GranularCssReadError`; вся публичная поверхность (CLI/doctor/explain/why-css, ошибки, warn'ы) переведена на
английский; JSDoc `cssFileAssetNames` соответствует валидации; `sideEffects: false`; `lib` без `DOM`; устаревшие
счётчики в `workspace.md`/`preset-core.md` обновлены (26 файлов / 345 тестов, пять кэшей), `SPEC.md` — «Defined by
0.7.x», publint-запись из `gotchas.md` снята, JSDoc `strictTokens` описывает фактическое поведение (skip +
`console.warn`). Подробности — в CHANGELOG пакета (`[Unreleased]`).
