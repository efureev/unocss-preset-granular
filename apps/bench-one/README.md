# `apps/bench-one`

Подопытный стенд замера: тот же скелет, что у `bench-zero`, плюс пресет и
**ровно один компонент** — `XhPanel` из `@feugene/heavy-package`. Его граф
разворачивает ещё четыре (`XhCard`, `XhButton`, `XhAlert`, `XhOverlay`).

## Раскладка ассетов

Она и есть предмет измерения. Шесть ролей, каждая отвечает на свой вопрос:

| ассет | роль | что внутри |
|---|---|---|
| `vue-*.js` | `vue` | рантайм фреймворка — из вердикта вычитается |
| `reset-*.{css,js}` | `reset` | ресет, одинаков в обоих стендах |
| `granular-*.css` | `granular` | **фундамент** пакета + `cssFiles` компонентов |
| `app-*.css` | `app` | preflight presetMini + утилиты от скана и safelist |
| `hpkg-*.{js,css}` | `pkg` | код компонентов и их SFC-стили |
| `index-*.js` | `entry` | код приложения |

Расщепление даёт `src/main.ts`: три раздельных динамических импорта
(`./reset`, `./granular` → `virtual:uno:granular.css`, `./app` →
`virtual:uno.css`). Без него фундамент, утилиты и ресет лежали бы одним
файлом, и приписать байты слою было бы нечем.

## Два инварианта, без которых замер врёт

**`App.vue` не содержит ни одного собственного класса.** Иначе `app-*.css`
перестанет быть атрибутируемым: нельзя будет сказать, пришла утилита из
компонента или из разметки стенда. Держит `expected-css.mjs`.

Отдельная грабля, на которую наступили при заведении стенда: UnoCSS сканирует
**текст файла**, а не разметку, и сгенерировал правило прямо из комментария,
где имя утилиты было приведено в качестве примера. Имён утилит в комментариях
`App.vue` нет намеренно.

**Трансформеров нет.** `transformerCompileClass` схлопывает классы в один
`.uno-<hash>` (в `app-1` в CSS лежит именно он) — после этого метрика классов
меряет количество хэшей, а не утилит. `transformerDirectives` не нужен: в
`heavy-package` нет ни одного `@apply`.

## `bench-meta.json`

`benchMetaPlugin` в `vite.config.ts` эмитит паспорт сборки: компоненты, темы,
safelist целиком и по компонентам, скан-globs, `cssFiles`. Считается из ТОЙ ЖЕ
резолюции, что питает пресет, — иначе знаменатель метрики safelist описывал бы
не тот CSS, который лежит рядом.

Файл ложится в `dist/`, а не в `dist/assets/`: иначе он попал бы в корпус
`verify-apps.mjs` и начал бы удовлетворять его подстрочные проверки сам.

## `expected-budget.mjs`

Сверяется в обе стороны — пропавшее ожидаемое нарушение такое же расхождение,
как новое. Сейчас там: одна мёртвая запись safelist (`shadow-legacy` —
намеренная фикстура), три недоказуемые ступени (`p-2`/`p-3`/`p-4`), одна
избыточная (`border`), ноль потребляемых-но-необъявленных токенов.

Байтовые числа лежат в `hints` и гейтом **не** являются: gzip невоспроизводим
между средами, а порог с потолка краснеет на честном росте.

## Команды

```bash
yarn workspace @feugene/granular-bench-one build
node scripts/verify-apps.mjs bench-one
yarn sizes           # отчёт против bench-zero
yarn sizes:check     # строгая сверка
yarn sizes:json      # то же машинно
```
