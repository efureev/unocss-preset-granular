# Строки и i18n

> См. также: [Темы и токены](./themes-and-tokens.md),
> [CLI `granular`](./cli.md).

Состав пакетов приложение объявляет ровно один раз — в `providers`. Какие из
них везут словари, по каким подпутям и на каких языках, знает только сборка, а
нужно это тому, кто пишет `createFintI18n({ loaders })`. Без канала между ними
этот список набивается руками и молча расходится с первым при появлении нового
пакета-спутника.

Пресет публикует **адреса, а не лоадеры**. Он не импортирует ни одного словаря,
не знает формата i18n-рантайма и не зависит от него. Импорты пишет
потребитель — он один знает, чем собирается его код.

## Что объявляет пакет

```ts
// src/granular-provider/index.ts
export const provider = defineGranularProvider({
  id: '@acme/ui',
  contractVersion: 1,
  packageBaseUrl: PACKAGE_BASE_URL,
  components: [...],
  i18n: {
    locales: ['en', 'ru', 'pt-BR'],
  },
})
```

`entry` по умолчанию `` `${id}/i18n` ``, `allEntry` — `` `${entry}/all` ``,
поэтому пакет, следующий конвенции, не объявляет ничего, кроме тегов.
Отсутствие всего поля `i18n` и означает «у пакета нет строк» — отдельного
флага для этого не нужно.

### Теги — это не имена импортов

В `locales` лежат **теги BCP 47** — верхние ключи коллекций лоадеров, те самые
строки, по которым ищет рантайм. Имя импорта — другая величина: `pt-BR` не
может быть идентификатором, и пакеты экспортируют его как `ptBR`. Пресет
выводит имя из тега (дефис убирается, следующий сегмент с заглавной) и
позволяет пакету перекрыть вывод там, где тот от конвенции отступил:

```ts
i18n: {
  locales: ['en', 'pt-BR'],
  // Только для тегов, чей экспорт назван иначе. Разреженное переопределение
  // поверх `locales`, а не второй их список.
  exportNames: { 'pt-BR': 'brazilian' },
}
```

Тег, из которого не выводится валидный идентификатор и для которого нет
переопределения, отвергается на регистрации — альтернатива этому
синтаксически битый импорт, сгенерированный внутри чужого приложения.

## Раскладка пакета

По модулю на локаль. Это требование не i18n-рантайма, а **бандлера**: только
такая раскладка позволяет потребителю выбросить языки, которых он не везёт.

```text
src/i18n/
  locales/en/…json
  locales/ru/…json
  en.ts          # экспортирует `en` — только английские лоадеры
  ru.ts
  index.ts       # барель именованных реэкспортов, без агрегата
  all.ts         # толстый агрегат для демо и тулинга
```

```ts
// src/i18n/en.ts
export const en = {
  en: {
    ui: () => import('./locales/en/ui.json'),
  },
}
```

```ts
// src/i18n/index.ts — `all` отсюда НЕ реэкспортируется: он затащил бы все
// языки обратно в граф любого, кто пишет `import { en }`.
export { en } from './en'
export { ru } from './ru'
```

```jsonc
{
  "sideEffects": false,
  "exports": {
    "./i18n":     { "types": "./dist/i18n/index.d.ts", "import": "./dist/i18n/index.js" },
    "./i18n/all": { "types": "./dist/i18n/all.d.ts",   "import": "./dist/i18n/all.js" }
  }
}
```

`./i18n` и `./i18n/all` — **разные** записи, а `sideEffects` не должен накрывать
модули локалей: иначе бандлер сочтёт каждый из них side-effecting и выбросить
откажется. Что подпути действительно объявлены в `exports`, проверяет
`granular doctor`; всё остальное здесь — на авторе пакета.

## Манифест

```ts
// vite.config.ts — тот же объект опций, что у пресета: манифест и CSS
// строятся из одной резолюции и разъехаться не могут.
import { granularI18nPlugin } from '@feugene/unocss-preset-granular/node'

plugins: [
  UnoCSS(),
  granularI18nPlugin(granularOptions, { locales: ['en', 'ru-RU'] }),
]
```

```ts
// vite-env.d.ts — тип берётся из `/runtime`, а не из `/node`: это браузерный
// код, и импорт node-входа ради типа утащил бы `node:fs` в бандл.
declare module 'virtual:granular-i18n' {
  import type { GranularI18nManifest } from '@feugene/unocss-preset-granular/runtime'

  const manifest: GranularI18nManifest
  export default manifest
}
```

```ts
// main.ts — импорты пишутся руками (или генерируются); манифест говорит какие.
import manifest from 'virtual:granular-i18n'
import { en, ru } from '@acme/ui/i18n'

const i18n = createFintI18n({
  locale: 'ru-RU',
  // Порядок значим: доноры раньше зависимых, лоадеры мержатся слева направо.
  loaders: [appEn, appRu, en, ru],
})
```

`getGranularI18nManifest(options, …)` отдаёт ту же структуру без плагина — для
конфигов, которым удобнее прокинуть её через `define:` самостоятельно.

### Что несёт связка

Вклад несёт **связки**, а не плоский список локалей: «что просило приложение» и
«что импортировать» — разные строки.

| Поле | Значение |
|---|---|
| `locale` | Объявленный тег — верхний ключ коллекции лоадеров. |
| `exportName` | Что писать в импорте: `ptBR` для тега `pt-BR`. |
| `serves` | Запрошенные теги, которые покрывает эта одна связка. |
| `via` | Как найдена: `exact`, `base` или `region`. |

Рядом с ними `manifest.locales` — объединение объявленных тегов, которые уедут
в бандл, то есть список `available` для `negotiateLocale`, а
`manifest.unserved` называет запрошенные теги, которых не отдаёт никто. Больше
этот промах не виден нигде: в рантайме согласование просто свалится в fallback.

## Подбор локали

Покрытие — не равенство строк. Каждый запрошенный тег проходит каскад, который
останавливается на первом попадании: на запрошенный тег приходится ровно один
объявленный, и один словарь не может уехать в бандл дважды.

| Шаг | Правило | Пример |
|---|---|---|
| `exact` | Совпадение без учёта регистра; побеждает написание пакета. | `ru` ← `ru` |
| `base` | Базовый язык запрошенного тега. | `ru` ← `ru-RU` |
| `region` | Обратный шаг: объявлен только региональный вариант. | `ru-RU` ← `ru` |

### Зачем нужен обратный шаг

Манифест решает, что попадёт в бандл, а это вопрос *доступности*. Без третьего
шага пакет, объявивший только `ru-RU`, выпадает из сборки, попросившей `ru`, и
согласование в рантайме больше не может выбрать то, что выбрало бы: локали нет
в бандле — значит нет и в `getAvailableLocales()`. Если подходящих региональных
вариантов несколько, берётся первый в порядке объявления, а `console.warn`
называет остальные: на сборке произвольный регион — это решение, а не деталь.

## Как проверить

```bash
granular doctor uno.config.ts --strict
```

Отчёт перечисляет локали каждого провайдера и поднимает `i18n-subpath`, когда
пакет объявил адрес, которого нет в его собственных `exports`. Иначе этот отказ
всплывает в сборке *потребителя* как `Failed to resolve import` — с именем
приложения, автор которого ничего этого не писал.

## Чего здесь намеренно нет

**Имён блоков.** Имя блока уже лежит внутри коллекции лоадеров вторым уровнем
ключа, поэтому поле в контракте стало бы вторым источником правды и разошлось
бы с реальностью. Цена названа, а не спрятана: столкновение блоков двух пакетов
на сборке не видно — и это нормально, совпадение блоков есть штатный мердж
лоадеров слева направо, а не ошибка.

**Лоадеров-функций.** Модуль провайдера исполняется в конфиге потребителя.
Функция утащила бы туда весь locale-JSON, а резолвилась бы относительно
провайдера, а не бандла приложения.
