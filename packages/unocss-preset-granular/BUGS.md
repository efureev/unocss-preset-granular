## Закрыто в 0.15.0 (заведено 2026-08-28 против 0.14.1)

Две находки из `@feugene/granularity` (ядро `0.38.0`, 78 компонентов) —
`token-undefined` слеп к `themes.tokensFile` и расхождение `granular tokens` с
`doctor` на инлайнимых токенах. Обе воспроизводились минимальным стендом на
data-URL и обе закрыты одной правкой.

Диагноз автора подтвердился дословно: `0.14.0` схлопнул три ответа про значение
токена в один `collectTokenLayers`, но **только для структурных слоёв**. Для CSS,
который пресет инлайнит целиком, правило доведено не было, и там оставалось два
независимых прохода: эмиссия **заменяла** провайдерский файл при app-override, а
диагностика **складывала** оба. Токен, снесённый подменой `tokensFile`, для неё
оставался заданным — и она молчала ровно в том случае, ради которого заведена.

Разбор вскрыл **третью** проблему того же корня, в исходном отчёте её не было:
доктор читал `provider.theme.themes[name]`, не глядя на `tokenDefinitions`, тогда
как `resolveThemes` разводит их через `else if` — структурная тема вытесняет
файловую, и файл в CSS не уезжает. Доктор разбирал файл-призрак и добавлял его
токены в «заданные».

Лечение общее: раскладка инлайнимых файлов вынесена в
`node-utils/inlinedCss.ts` (`resolveInlinedCssSources`), из неё берут и эмиссия,
и обе команды. Обход идёт по `resolution.themes.items`, что закрывает третью
проблему по построению. Заодно `pickThemeUrl` перестал подписывать
app-override как `provider '<id>'`: метка стала происхождением токена в отчёте,
и врать ей больше нельзя.

Токены инлайнимого CSS теперь попадают в группы `provider` / `app` со значением
и файлом-источником, а не в «ничьи». На провайдере, отдающем палитру обычным
`tokens.css`, `granular tokens` до правки показывал весь набор как
`origin: none` — то есть не отвечал ни на что.

Прогон после правок: `yarn test:granular` — 451/451 (31 файл); coverage
95.1 / 87.7 / 97.7 при порогах 90 / 85 / 90; `verify-apps` — 6/6 приложений,
54 проверки; `yarn check:docs` — 13 пар; замки `preset.node.overrides.test.ts`
(19 тестов) и `verify-apps` прошли **без единой правки** — эмиссия не поехала.
Стенд из исходного отчёта после правки даёт:

```text
штатно      | --x-radius в CSS: true  | token-undefined: @acme/ui:XCard:x-missing
tokensFile  | --x-radius в CSS: false | token-undefined: @acme/ui:XButton:x-radius,@acme/ui:XCard:x-missing

granular tokens → x-radius: origin=provider | undefinedCount: 0
granular doctor → x-radius в undefinedTokens: false
```
